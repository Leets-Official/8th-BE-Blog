## 1. 실습

### 1) AWS 계정 준비
- 신규 계정을 **무료 플랜(Free plan)**으로 만들었다. 무료 플랜은 유료 플랜으로 업그레이드하기 전까지 요금이 청구되지 않는다.
- **예산 알림:** 템플릿의 *제로 지출 예산*을 만들어, 실제 요금이 0.01 USD를 넘으면 메일이 오게 했다.
- **루트 계정 MFA:** 인증 코드 재전송 제한에 걸려 설정 중이다.

### 2) EC2 인스턴스 생성

| 항목 | 설정 | 이유 |
|---|---|---|
| 리전 | 아시아 태평양 (시드니) `ap-southeast-2` | 무료 플랜 계정은 리전이 하나로 지정된다. 서울을 쓰려면 유료 플랜이 필요해서 시드니에서 진행했다 |
| AMI | Ubuntu Server 24.04 LTS | 강의자료 기준 |
| 인스턴스 유형 | `t3.micro` (vCPU 2, 메모리 1GiB) | 프리 티어 대상 |
| 스토리지 | 8GiB gp3 | 기본값 |
| 키 페어 | RSA, `.pem` | 로컬 사용자 폴더에 보관하고 Git에는 올리지 않는다 |
| 보안 그룹 인바운드 | SSH 22 → 내 IP / HTTP 80 → `0.0.0.0/0` | SSH는 나만, 웹은 누구나 접속 |

### 3) SSH 접속과 Docker 설치

Windows PowerShell에서 접속했다.

```powershell
cd $HOME                                   # 키 파일이 있는 사용자 폴더로 이동
ssh -i leets-key.pem ubuntu@<퍼블릭 IP>
```

처음에는 관리자 PowerShell이 `C:\Windows\System32`에서 열려서 키 파일을 찾지 못했고, `Permission denied (publickey)`가 났다. 키 파일이 있는 폴더로 이동한 뒤 접속에 성공했다.

```bash
sudo apt update
sudo apt install -y docker.io
sudo usermod -aG docker ubuntu   # 다시 접속하면 sudo 없이 docker 사용 가능
exit
# 재접속 후
docker run hello-world
```

### 4) nginx 컨테이너 실행

```bash
docker run -d -p 80:80 nginx
docker ps
```

`docker ps` 결과의 `PORTS`가 `0.0.0.0:80->80/tcp`로 나와서, EC2의 80번 포트가 컨테이너의 80번 포트에 연결된 것을 확인했다.

### 5) 브라우저 확인

`http://<퍼블릭 IP>`에 접속해 **Welcome to nginx!** 페이지를 확인했다. 실습을 마친 뒤 인스턴스를 **중지**했다. 중지했다가 다시 시작하면 퍼블릭 IP가 바뀐다.

## 2. 개념 정리

### EC2 / RDS / S3
- **EC2:** 클라우드에서 빌려 쓰는 가상 컴퓨터로, 서버 애플리케이션을 실행하는 곳이다.
- **RDS:** AWS가 설치·백업·패치를 대신 관리해 주는 관계형 데이터베이스 서비스다.
- **S3:** 이미지 같은 파일을 객체 단위로 저장하는 저장소다. DB에는 파일 대신 S3 URL만 저장한다.

### 이미지 vs 컨테이너
- **이미지**는 프로그램과 실행 환경을 담은 읽기 전용 설계도(붕어빵 틀)다.
- **컨테이너**는 이미지를 실제로 실행한 것(붕어빵)이다. 이미지 하나로 컨테이너를 여러 개 만들 수 있고, 컨테이너를 지워도 이미지는 남는다.

### `-p 8080:8080`의 의미
- `-p 호스트포트:컨테이너포트` 형식이다. EC2(호스트)의 8080번 포트로 들어온 요청을 컨테이너 안의 8080번 포트로 전달한다.
- 이번 실습의 `-p 80:80`은 EC2의 80번 → nginx 컨테이너의 80번이다.
- 요청 경로: 사용자 → 인터넷 → 보안 그룹(포트 허용) → EC2 포트 → Docker 포트 매핑 → 컨테이너. **보안 그룹과 `-p` 둘 다 열려 있어야** 접속된다.

### 배포 실패 체크리스트
1. 인스턴스가 "실행 중"이고 상태 검사를 통과했는가?
2. 보안 그룹 인바운드 규칙에 해당 포트(22/80/8080)가 열려 있는가? SSH는 내 IP가 바뀌지 않았는가?
3. 접속 주소가 맞는가? (인스턴스를 중지했다 켜면 퍼블릭 IP가 바뀐다. `https`가 아니라 `http`)
4. 컨테이너가 실행 중인가? (`docker ps`, 꺼졌다면 `docker ps -a`와 `docker logs <컨테이너>`)
5. 포트 매핑(`-p`)이 애플리케이션 포트와 맞는가?
6. SSH 접속 실패 시: 키 파일 경로·권한과 사용자 이름(`ubuntu`)이 맞는가?

## 3. 보안·비용 메모
- `.pem` 키 파일, 비밀번호, 퍼블릭 IP는 저장소와 스크린샷에 올리지 않았다.
- SSH(22)는 내 IP에만 열었다.
- 실습이 끝나면 인스턴스를 중지한다. 종료(Terminate)는 복구할 수 없다.
