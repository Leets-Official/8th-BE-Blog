# 인증·인가 구현 검증

브랜치: `강현우/6주차`. 작업 전 기준: `223ee8e`.

## Standards

독립 리뷰에서 지적한 코어의 JPA·JWT·HTTP 의존은 포트와 트랜잭션 어댑터로 분리했다. 신규 API의 성공 상태와 의미 오류 코드를 Swagger에 추가했다. 인증 코어 경계를 ArchUnit으로 검사한다. 재검토에서 남은 차단 수준의 규칙 위반은 없다. 짧은 변수명과 문자열 토큰 종류는 향후 가독성 개선 여지가 있다.

## Spec

기존 사용자 중복 점검 및 필수 유니크 인덱스 확인, 카카오 중복 계정 안내, 동시 가입·재발급 테스트를 보강했다. 재검토에서 남은 주요 명세 결함은 없다.

## 검증 결과

- `./gradlew test --console=plain`: 성공. 총 122개, 실패 0, 오류 0, 건너뜀 0.
- 회원가입 해시·정규화, 로그인 거절 일관성, 보호 API·토큰 변조·만료·종류 검사, RTR 재사용 폐기 및 동시 요청, 기기별 로그아웃을 검증했다.
- 게시글·댓글 소유권 거절과 데이터 보존, 신고 관리자 제한, 기존 검색·신고·데이터 재시작 시나리오를 검증했다.
- 카카오 REST HTTP 경계의 토큰 교환·사용자 조회와, 가입·재로그인·중복 계정·이메일 미제공·일회용 코드 재사용 거절을 검증했다.
- 카카오 실계정 로그인은 앱 설정 부재로 미검증이다. 설정 순서는 `auth-security.md`를 따른다.

초기 회원가입·JWT·RTR 구현은 공유 인증 기반으로 한 커밋에 묶었고, 게시글·댓글·신고·카카오는 각각 별도 커밋으로 기록했다. 이후 브랜치를 6주차로 옮기고 로컬 5주차 브랜치는 작업 전 기준으로 복원했다. 원격 푸시는 하지 않았다.
