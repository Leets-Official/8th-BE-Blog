# 03: 실패 응답 생성 인터페이스 정리

Status: resolved

**Blocked by:** None (can start immediately).

**What to build:** 지원하는 실패 생성 경로와 실제 오류 응답이 기존 `data: null` 계약을 지키도록 한다.

## Scope

[명세](../spec.md)에 따라 데이터를 받는 실패 생성 메서드의 사용처를 확인하고, 오류 응답의 `data: null` 계약에 맞춰 불필요한 오버로드를 제거한다.

## Completion criteria

- [x] 사용처 확인 결과를 기록하고 필요한 호출부를 두 인자 실패 생성 메서드로 이전한다.
- [x] 지원하는 실패 생성 경로와 대표 HTTP 오류 응답에서 명시적인 `data: null`을 검증한다.
- [x] 성공 응답과 기존 의미 코드·HTTP 상태 매핑을 유지한다.
- [x] 전체 테스트가 통과하며 응답 객체 전체 구조를 개편하지 않는다.

## Comments

- 코드베이스의 실패 생성 호출은 모두 두 인자 버전을 사용했다. 데이터 인자를 받는 오버로드는 사용처가 없어 제거했고 호출부 이전은 필요하지 않았다.
- 기존 공통 응답 테스트에 직렬화 결과의 `data` 필드 존재 및 null 값 검증을 보강했다. 대표 HTTP 오류 응답은 본문 오류 통합 테스트에서 검증한다.
