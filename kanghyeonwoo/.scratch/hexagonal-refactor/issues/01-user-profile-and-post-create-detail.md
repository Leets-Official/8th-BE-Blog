# 01: 사용자 프로필과 게시글 생성·상세 조회를 헥사고날 경계로 이관

**What to build:** 기존 게시글 생성과 상세 조회 API가 사용자 프로필을 확인하면서 동작하고, 업무 규칙과 조회 결과가 HTTP·JPA 구현에 묶이지 않도록 한다.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] `user` 모듈이 현재 이름·이메일 프로필 데이터를 소유하고 공개 프로필 조회를 제공한다. 인증 기능은 추가하지 않는다.
- [ ] 게시글 생성과 상세 조회가 `blog`의 유스케이스를 거치며 작성자 조회는 공개 사용자 포트를 사용한다.
- [ ] 도메인·유스케이스 모델은 Spring/JPA 및 웹 DTO에 의존하지 않고, JPA 모델은 모듈 내부에 둔다.
- [ ] 기존 경로, 요청·응답 필드, 상태 코드, API 오류 코드, DB 스키마와 데이터가 유지된다.
- [ ] 웹 어댑터가 의미별 업무 실패를 기존 API 오류 응답으로 변환하고, 트랜잭션 데코레이터가 필요한 작업의 경계를 제공한다.
- [ ] 단위 테스트, 저장소 통합 테스트, API 계약 테스트와 초기 ArchUnit 규칙으로 이 경계를 검증한다.
