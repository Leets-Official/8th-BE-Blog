# Datafaker 기반 목 데이터 생성 전환

상태: 사용자 승인 후 티켓 발행 및 구현·검증·로컬 DB 입력 완료. 티켓은 resolved.

## 작업 시작 시점

- mock-data 프로필의 생성기, seedMockData 실행 명령, 재실행 중복 방지 테스트가 작업 트리에 있다.
- 사용자 이름과 게시글·댓글 본문이 고정 문자열로 생성된다.
- 중단 후 로컬 H2를 확인한 결과 mock-user 전용 이메일 사용자는 0명이다. 앞선 목 데이터 주입은 완료되지 않았다.
- 기존 Mermaid 상태도 문서 변경과 기존 DB 데이터는 보존한다.

## 01. Datafaker로 사용자·게시글·댓글 생성 및 로컬 DB 주입

Blocked by: 없음.

### 제공하는 동작

seedMockData 명령을 실행하면 Datafaker로 다양한 사용자 이름과 게시글·댓글 내용을 만들고 기존 로컬 H2에 추가한 뒤 종료한다. 기존 사용자·게시글·댓글을 삭제하거나 덮어쓰지 않으며, 반복 실행 시 같은 목 데이터를 중복 생성하지 않는다.

### 완료 조건

- 프로젝트 Java 버전과 호환되는 Datafaker 버전을 고정해 추가하고, 기존 고정 문자열 생성 부분을 교체한다.
- locale과 난수 seed를 명시해 동일 라이브러리 버전·생성 순서에서 텍스트 생성을 재현한다. DB ID·생성 시각까지 고정하지 않는다.
- 기본 데이터는 사용자 5명, 게시글 12개, 댓글 36개다. 대댓글 12개, 숨김 게시글 2개, 숨김 댓글 2개, 삭제 댓글 2개를 유지한다.
- 작성자·게시글·부모 댓글의 관계와 공개·삭제 상태는 생성기가 명시적으로 구성한다. 라이브러리는 값 생성을 담당한다.
- 사용자 이름 50자, 게시글 제목 150자 등 저장 제약을 만족한다. 목 데이터 이메일은 기존 전용 규칙으로 유일하게 유지한다.
- 게시글의 목 데이터 식별 접두어와 검색에 필요한 표식을 유지한다. 기존 신고 시연용 moderation-demo는 변경하지 않는다.
- 기존 고정 문자열 데이터가 이미 있는 경우에도 자동 삭제·덮어쓰기하지 않는다. 재실행 중복 방지와 기존 데이터 보존을 검증한다.
- 테스트는 특정 생성 이름·문장 대신 개수, 필드 제약, 관계, 상태, 검색·페이징, 재실행 결과를 검증한다.
- 실행 방법과 생성 범위를 문서화한다. 검증 후 기존 로컬 DB에 실제 주입하고 개수 및 샘플 ID를 확인한다.

## 분할 이유

의존성 추가부터 실제 데이터 생성·저장·검증까지 하나의 작은 기능으로 완료할 수 있다. 라이브러리 추가, 생성기 변경, 테스트를 별도 수평 티켓으로 나누지 않는다.
