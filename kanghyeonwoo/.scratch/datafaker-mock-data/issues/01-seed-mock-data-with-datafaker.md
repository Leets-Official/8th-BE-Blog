# 01: Datafaker 기반 사용자·게시글·댓글 생성과 DB 주입

**What to build:** seedMockData 명령을 실행하면 Datafaker로 다양한 사용자 이름과 게시글·댓글 내용을 생성하고 기존 로컬 H2 DB에 추가한 뒤 종료한다. 기존 데이터는 보존하고 재실행 시 같은 목 데이터를 중복 생성하지 않는다.

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] 프로젝트 Java 버전과 호환되는 Datafaker 버전을 고정해 추가하고, 기존 고정 문자열 기반 목 데이터 생성을 교체한다.
- [x] locale과 난수 seed를 명시한다. 동일 라이브러리 버전·생성 순서에서 텍스트를 재현하되 DB ID·생성 시각은 고정하지 않는다.
- [x] 사용자 5명, 게시글 12개, 댓글 36개를 생성한다. 대댓글 12개, 숨김 게시글 2개, 숨김 댓글 2개, 삭제 댓글 2개를 유지한다.
- [x] 작성자·게시글·부모 댓글 관계와 공개·삭제 상태는 생성기가 구성하고 Datafaker는 값 생성을 담당한다.
- [x] 사용자 이름 50자, 게시글 제목 150자 등 저장 제약을 만족한다. 전용 목 데이터 이메일 규칙으로 유일성과 재실행 식별을 유지한다.
- [x] 게시글의 목 데이터 식별 접두어와 검색용 표식을 유지한다. 기존 신고 시연용 moderation-demo는 변경하지 않는다.
- [x] mock-data 프로필에서만 생성한다. 기존 seedMockData 명령으로 서버를 상시 실행하지 않고 생성·커밋 후 종료할 수 있다.
- [x] 기존 사용자·게시글·댓글을 삭제하거나 덮어쓰지 않는다. 이전 고정 문자열 목 데이터가 이미 있으면 중복 생성 없이 보존한다.
- [x] 테스트는 특정 생성 이름·문장 대신 개수, 필드 제약, 관계, 상태, 검색·페이징, 재실행 중복 방지 및 기존 데이터 보존을 검증한다.
- [x] 실행 방법과 생성 범위를 문서화한다. 검증 후 기존 로컬 DB에 실제 데이터를 추가하고 개수와 샘플 ID를 확인한다.

## 참고

## Answer

Datafaker 2.7.0과 ko locale·seed 20261026을 적용했다. 생성기는 이름·제목·본문과 길이 제한을 담당하고, 시더는 작성자·게시글·대댓글 관계 및 숨김·삭제 구성을 담당한다. 전용 이메일을 유지해 구형 목 데이터도 덮어쓰지 않는다.

전체 테스트 82개 통과(실패·오류·건너뜀 0). 같은 seed의 텍스트 재현, 다른 seed의 변화, 개수·상태·관계, 검색·페이징, 재실행 중복 방지, 기존 일반 데이터와 구형 목 데이터 보존을 검증했다. 리뷰의 조회 순서 의존 권고는 상태 기반 fixture 선택 및 조건 기반 응답 검증으로 수정했다.

임시 메모리 DB로 CLI 생성·종료를 검증한 뒤 기존 로컬 H2 data/blog에 실제 주입했다. 기존 사용자 1명·게시글 2개를 유지하고 사용자 5명·게시글 12개·댓글 36개를 추가했다. 실제 사용자 ID는 2~6, 게시글 ID는 3~14, 댓글 ID는 1~36이다. 재실행 후에도 총 사용자 6명·게시글 14개·댓글 36개를 유지했다. 이 ID는 현재 로컬 실행 결과이며 생성 규칙에 고정하지 않는다.
