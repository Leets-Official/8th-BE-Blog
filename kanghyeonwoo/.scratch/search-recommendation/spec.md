# 검색어 추천 및 트렌드

Status: implementing

## 확정한 결정

- 유사 검색어는 의미가 아닌 철자 유사도를 기준으로 추천한다.
- 검색어 사전은 초기 등록 데이터로 시작한다. 실제 게시글 검색 결과가 있는 검색어를 사전에 추가한다.
- 검색 이력은 검색어 사전 등록 여부와 별도로 기록하고 트렌드 계산에 사용한다.
- 파일 기반 H2로 데이터를 유지한다. 유사도 탐색은 Java 서비스에서 구현한다.
- 추가 API는 다음 3개로 구성한다.
  - `GET /search/suggestions?keyword=...`: 철자가 비슷한 검색어 추천
  - `GET /search/trends`: 급상승 검색어 조회
  - `GET /search/keywords/{keywordId}/stats`: 특정 검색어의 시간대별 검색량과 상승률 조회
- 실제 게시글 검색은 기존 `GET /posts?keyword=...`를 확장한다.
- 트렌드는 요청 시각 기준 최근 60분과 그 이전 60분의 검색량을 비교한다.
- 자동완성 요청은 검색량에 포함하지 않는다. 실제 게시글 검색만 집계한다.
- 같은 세션에서 같은 검색어를 5분 안에 반복 검색하면 한 번으로 집계한다.
- 검색어는 Unicode NFC 정규화, 영문 소문자화, 앞뒤 공백 제거, 연속 공백의 단일 공백화를 적용한다. 내부 공백을 모두 제거하지는 않는다.
- 정규화 규칙은 게시글 검색, 사전 등록과 중복 집계에 일관되게 적용한다. 기존 게시글 데이터와의 검색 일치 방식은 구현 설계에서 정한다.
- 초기 검색어 사전을 제공한다. 자동 등록은 게시글 검색 결과가 있고, 정규화한 검색어 길이가 2~50자이며 한글·영문·숫자를 하나 이상 포함할 때만 허용한다. 결과가 없는 검색어는 자동 등록하지 않는다.
- 익명 사용자는 서버가 발급한 세션 쿠키로 구분한다. 쿠키 삭제나 다른 브라우저 사용은 별도 세션으로 취급한다.
- 중복 집계 제외는 같은 세션·정규화 검색어의 마지막 집계 시각부터 5분을 기준으로 한다. 제외된 요청은 마지막 집계 시각을 갱신하지 않는다.
- Java 메모리의 BK-tree로 사전 후보를 탐색하고 Levenshtein 편집 거리를 사용한다. 한글은 자모 분해 없이 NFC 정규화된 글자 단위로 비교한다.
- 정규화 입력이 2~4자면 편집 거리 1 이하, 5자 이상이면 거리 2 이하인 단어를 추천 후보로 삼는다.
- 추천은 입력과 동일한 단어를 제외하고, 편집 거리 오름차순 → 최근 1시간 집계 검색량 내림차순 → 정규화 검색어 사전순으로 최대 5개를 반환한다. 후보가 없으면 빈 목록을 반환한다.
- 급상승 후보는 최근 1시간 집계 검색량이 5회 이상이고 직전 1시간보다 증가한 단어다.
- 상승 점수는 `(최근 검색량 - 직전 검색량) / max(직전 검색량, 5)`로 계산한다. 점수 내림차순, 최근 검색량 내림차순으로 최대 10개를 반환한다.
- 검색 이력은 30일 보관한다. 통계는 최근 24시간의 시간대별 검색량을 제공하고 검색이 없는 구간은 0으로 채운다. 현재 시간대는 부분 집계임을 표시한다.
- 실제 게시글 검색 중 검색어가 있는 첫 페이지 요청만 기록한다. 결과가 없어도 집계하지만 사전에는 자동 등록하지 않는다. 빈 검색어로 목록만 조회하는 요청은 집계하지 않는다.
- 검색어가 있는 검색 요청의 정규화 검색어 길이는 2~50자로 제한한다.
- 단일 서버로 실행한다. 시작 시 DB 사전에서 BK-tree를 재구성하고 새 사전 단어가 등록되면 반영한다. 동시 요청의 중복 사전 등록과 중복 집계를 방지한다.
- 검색어별 분 단위 집계 테이블을 추가한다. 정확한 60분 구간의 부분 분은 원본 이력으로 보정한다.
- 데모 프로필에서 예시 작성자·게시글·검색 데이터의 실제 DB 삽입까지 구현한다. 기본 실행에서는 데모 이력을 넣지 않는다.
