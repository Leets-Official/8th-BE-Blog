# 4주차 검색 기능 리뷰

기준 커밋: 774f4f599552e560240ced8e6fa3d77f9b733b4d. Standards와 Spec을 별도 리뷰 에이전트가 검토하고 수정 사항을 재검토했다.

## Standards

문서화된 코딩 규칙 위반은 없었다. 검색어 한 개의 통계를 조회할 때 모든 검색어를 반복 집계하는 성능 문제 1건을 발견했다. 버킷·원본 경계 조회 모두 keyword_id 조건을 적용해 해결했고 재검토에서 확인했다.

추가 잠금 변경도 재검토했다. 검색 쓰기 잠금은 트랜잭션 시작 전에 획득하고 커밋·롤백 후 해제하며, 트리 잠금은 재구성·후보 탐색에 일관되게 적용된다. 남은 지적 사항 0건.

## Spec

합의한 동작의 결함은 발견되지 않았다. 추천·급상승의 동점 정렬과 저장 실패 시 롤백의 테스트가 부족하다는 검증 공백을 확인했다. API 테스트로 모두 보강해 통과했고 재검토에서 확인했다.

잠금 교체 후에도 커밋 이후 사전 반영, 중복 집계 제외, 이력·버킷·중복 상태의 원자적 변경, 데모 데이터의 단일 트랜잭션 삽입이 유지됨을 재검토했다. 남은 지적 사항 0건.

## 동시성 회귀 수정

전체 테스트에서 Java 21 가상 스레드의 동시 검색 중 500 응답이 발생했다. Hikari 연결 풀을 2개, 연결 대기를 1초로 제한한 단독 테스트로 재현했다. 트랜잭션 설정은 유지하고 DB 작업 중 사용하는 synchronized 잠금을 ReentrantLock으로 바꿔 해결했다. 트리 갱신도 같은 잠금 방식을 적용했다. 잠금 대기로 인한 가상 스레드의 carrier 점유를 피하면서 커밋까지의 직렬화를 유지한다.

## 검증 결과

- `./gradlew check bootJar`: 성공, 14개 테스트 클래스의 55개 테스트 통과. 실패·오류·생략 0개.
- 파일 기반 H2에 실제 데모 데이터 삽입 후 추천·급상승·통계 API를 HTTP로 확인했다.
- sprng → spring, 급상승 spring → jpa → java, 최근·직전 검색량 10·2 및 점수 1.6을 확인했다.
- 파일 DB 재시작 시 데이터 유지와 중복 삽입 방지를 통합 테스트로 확인했다.
