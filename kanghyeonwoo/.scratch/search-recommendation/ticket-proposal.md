# 검색 기능 티켓 분할안

Status: implemented

분 단위 집계 테이블과 개발용 데이터 자동 삽입까지 구현 범위에 포함한 제안이다. 사용자 구현 지시에 따라 로컬 트래커에 티켓별로 발행했다. API 3개와 기존 게시글 검색 확장을 각각 검증 가능한 단위로 나눈다. 애플리케이션에는 UI가 없으므로 API 호출과 통합 테스트로 시연한다.

## 01: 게시글 검색 정규화와 세션별 검색 이력 기록

- Blocked by: 없음.
- 제공 동작: 정규화한 검색어로 기존 게시글 검색을 실행하고 유효한 첫 페이지 요청을 세션별로 중복 없이 기록한다. 재시작해도 검색 이력이 유지된다.
- 범위: 파일 기반 H2, 테스트 DB 격리, 기존 제목의 정규화 및 기존 데이터 보완, 검색어·검색 이력·중복 집계 상태 테이블, 서버 세션 쿠키, 검색어 사전 등록 조건.
- 검증: NFC·대소문자·공백·리터럴 포함 검색, 2~50자 검증, 빈 검색어 목록과 후속 페이지 제외, 결과 없는 검색 집계, 5분 경계, 동시 중복 요청, 사전 승격, 파일 DB 재접속, 기존 게시글 CRUD 회귀.
- 수명주기: 검색 이력의 30일 보관과 오래된 중복 판정 상태 정리까지 포함한다. 입력 검증과 게시글 검색 실패 시에는 검색량을 남기지 않는다. 추적 저장 실패 시 부분 기록 없이 요청을 실패 처리한다.

## 02: BK-tree 기반 유사 검색어 추천 API

- Blocked by: 01.
- 제공 동작: 초기 사전 및 검색으로 추가된 사전 단어에서 철자가 비슷한 검색어를 최대 5개 추천한다.
- 범위: 시작 시 DB 사전으로 BK-tree 구성, 초기 단어 멱등 등록, 커밋 후 신규 사전 반영과 갱신 실패 시 재구성, 동시 탐색·변경 처리, 추천 API와 공통 응답·입력 검증.
- 규칙: 입력 2~4자는 거리 1 이하, 5~50자는 거리 2 이하. 동일 단어 제외. 편집 거리, 최근 1시간 집계 검색량, 검색어 사전순으로 정렬한다. 최근 검색량은 이 단계에서 원본 이력으로 집계할 수 있다.
- 검증: 한글·영문 오타, 빈 후보, 임계 거리, 동점, 전체 사전 편집 거리 계산과 후보 일치, 재시작과 사전 추가 반영. 추천 요청 자체는 검색량을 생성하지 않는다.

## 03: 분 단위 집계를 이용한 급상승 검색어 API

- Blocked by: 01.
- 제공 동작: 게시글 검색량을 분 단위로 누적하고 최근 60분의 급상승 검색어 상위 10개를 조회한다.
- 범위: 검색어별 분 단위 집계 테이블과 유니크 제약, 검색 이력·마지막 집계 시각·버킷 증가의 원자적 처리, 기존 이력의 버킷 초기 집계, 급상승 API, 30일이 지난 버킷 정리.
- 규칙: 최근 60분 검색량 5 이상이고 직전 60분보다 증가한 검색어만 포함. 점수는 증가량을 직전 검색량과 5 중 큰 값으로 나눈다. 점수와 최근 검색량 내림차순 후 검색어 사전순으로 정렬한다. 결과 없는 검색어도 집계에 포함한다.
- 정확성: 요청 시각을 한 번 고정하고 시작 포함·끝 제외로 계산한다. 전체 분은 버킷에서, 경계에 걸친 부분 분은 원본 이력에서 계산하여 원래의 60분 구간 정의를 유지한다. 초기 집계·재시작·동시 검색에서 누락이나 이중 집계가 없어야 한다.
- 검증: 직전 검색량 0, 최소 검색량, 동점, 분·60분 경계, 이력과 버킷 합계 일치, 동시 요청, 재시작 및 기존 이력 보완, 빈 순위.
- 독립성: 02의 추천 API나 BK-tree 구현은 선행 조건이 아니다.

## 04: 검색어별 최근 24시간 통계 API

- Blocked by: 03.
- 제공 동작: 특정 검색어의 최근 24개 시간대별 검색량과 최근·직전 60분 검색량 및 상승 점수를 조회한다.
- 범위: 분 단위 집계에서 시간 단위 통계를 생성하고, 60분 비교는 03과 같은 계산 규칙을 공유한다.
- 규칙: Asia/Seoul 기준 현재 시간대를 포함해 시간순 24개 구간을 반환한다. 빈 구간은 0, 현재 구간은 요청 시각까지의 부분 집계로 표시한다. DB 시각은 UTC. 미존재 검색어 ID는 404, 이력이 없는 등록 검색어는 0을 반환한다.
- 검증: 고정 Clock에서 24개 구간, 시간대와 날짜 경계, 0 채움, 현재 부분 구간, 미존재 ID, 급상승 API와 동일한 집계값. 통계 조회는 검색량을 만들지 않는다.

## 05: 개발용 예시 데이터 자동 삽입과 API 시연

- Blocked by: 02, 04. 04가 03과 01에 의존하므로 중복된 선행 관계는 나열하지 않는다.
- 제공 동작: 명시적으로 선택한 개발 데모 프로필로 실행하면 예시 작성자·게시글·검색어·이력·중복 판정 상태·분 단위 집계가 삽입되고 세 검색 API와 기존 게시글 검색을 즉시 시연할 수 있다.
- 예시: 검색어 8개, 이력 43개, 중복 판정 상태 43개, 분 단위 집계 8개. 실제 검색 결과와 사전 승격을 확인할 게시글·작성자 데이터도 함께 제공한다.
- 시간: 테스트는 예시 데이터 기준 시각으로 Clock을 고정한다. 개발 데모는 삽입 시각 기준 분 경계에 맞춰 모든 시각을 같은 간격만큼 이동하여 최근 순위가 나타나게 한다. 시간 이동은 테스트 세션의 중복 판정 시각에도 동일하게 적용한다.
- 멱등성: 기존 데이터는 덮어쓰거나 삭제하지 않고, 전용 데모 데이터의 안정적인 식별자로 중복 삽입을 막는다. 기본 프로필과 일반 테스트 실행에는 데모 데이터를 자동 삽입하지 않는다. 데모 데이터 재생은 일회성으로 하며 매 시작 시 검색 시각을 새로 갱신하지 않는다. 시간이 지나면 데모 순위도 자연스럽게 만료됨을 안내한다.
- 검증: 실제 DB 삽입 후 sprng → spring, 스프링부투 → 스프링부트·스프링, 급상승 spring → jpa → java 및 시간대별 통계를 API로 확인한다. 재시작 시 중복 없음, 기본 프로필에서 미삽입, 초기화 완료 후 BK-tree의 사전 반영을 확인한다.
- 문서: 데모 프로필 실행법, 쿠키를 유지한 검색 예시, 세 API 호출과 기대 결과, 고정 시각 테스트 및 데모 데이터 만료 동작을 설명한다.
