# 인증·인가 및 카카오 로그인

Status: Approved

## 확정한 요구사항

- Spring Security Stateless, BCrypt, JJWT 0.12+, Access Token 10분, Refresh Token 7일.
- 사용자 프로필과 인증 계정은 같은 사용자 ID를 공유한다. 기존 프로필과 콘텐츠는 보존하되 비밀번호가 없는 기존 사용자는 로그인할 수 없다. 비밀번호 설정·복구는 이번 범위에서 제외한다.
- 이메일·닉네임 사전 중복 검사 및 DB 유니크 제약으로 가입 경합을 방어한다.
- 여러 기기에서 로그인할 수 있다. 로그인별 Refresh Token을 관리하며 회전 시 수명은 다시 7일이다.
- 이전 Refresh Token 재사용 시 해당 로그인의 토큰 계열 전체를 폐기한다. 동시 재발급은 하나만 성공한다.
- 로그아웃은 해당 로그인만 종료한다. 발급된 Access Token은 만료까지 최대 10분 유효하다.
- 게시글·댓글·신고의 행위자는 요청 ID가 아닌 인증 주체에서 얻는다. 댓글 생성·수정·삭제 API도 구현한다.
- 자원 소유권은 서비스 계층에서 검사한다. 신고 목록 조회·처리는 관리자 전용이다. 관리자는 운영 환경에서 별도로 지정하며 공개 승격 API는 제공하지 않는다.
- 필터의 401/403도 기존 ApiResponse 계약을 준수한다. 도메인·유스케이스 경계는 기존 ADR-0001을 따른다.
- RTR, 로그아웃, Swagger BearerAuth 및 카카오 OAuth2를 모두 포함한다.
- 카카오 고유 ID로 신원을 식별한다. 신규 카카오 가입 시 기존 이메일과 충돌하면 가입·병합을 막고 기존 로그인 수단 이용을 안내한다. 이메일 미제공 시 가입을 중단한다.
- 신규 카카오 사용자는 짧은 유효기간의 가입용 토큰으로 닉네임 입력 절차를 마친다. 가입 완료 시 이메일·닉네임 중복을 다시 검사한다.
- 서버가 카카오 로그인 시작·콜백을 처리하고 state를 검증한다. 프런트엔드에는 JWT 대신 로그인 시작 브라우저에 연결된 일회용 교환 코드를 전달한다. 프런트엔드가 이를 서버에 제출해 JWT를 받는다.
- 카카오 설정은 환경변수로 주입하며 카카오 응답을 대체한 테스트를 작성한다. 실제 연동 검증에는 카카오 앱 설정이 필요하다.
- 단위·MockMvc 테스트 및 전체 ./gradlew test로 검증한다.

## 추가 확정

- JWT는 JSON 응답 본문으로 전달하며 재발급·로그아웃은 Refresh Token을 요청 본문으로 받는다.
- 이메일은 trim 후 소문자로 통일하고, 닉네임은 trim하되 대소문자를 구분한다. 비밀번호는 변형하지 않는다.
- 기존 데이터의 닉네임 충돌을 자동 수정하지 않는다. 충돌을 확인하고 정리한 후 유니크 제약을 적용한다.
- 카카오 앱 설정은 아직 없으며 실제 REST 연동 코드·테스트·설정 안내를 먼저 완료한다. 실계정 로그인 검증은 설정 이후 수행한다.
- 각 티켓 검증 완료 시 커밋한다.
