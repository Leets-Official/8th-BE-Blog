# 02: 중복 방지를 포함한 게시글 신고 접수

**What to build:** 사용자가 게시글을 신고하면 신고 당시 제목·본문을 보존한 PENDING 신고가 생성된다. 동일 사용자의 같은 대상 신고는 동시 요청에서도 한 번만 저장된다.

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] POST /posts/{postId}/reports에서 reporterId와 reason을 받고 HTTP 201 및 문자열 S201 코드로 신고 ID, 대상 종류·ID, 상태를 반환한다.
- [x] 존재하는 사용자와 대상만 허용한다. 본인 게시글 신고는 403, 없는 사용자·대상 및 숨김 게시글 신규 신고는 404다.
- [x] 신고 사유는 공백 불가·최대 255자이며 잘못된 ID·입력은 400이다.
- [x] 게시글 ACTIVE/HIDDEN 상태와 신고 PENDING/RESOLVED 상태를 도입하고 기존 게시글은 ACTIVE, 기존 신고는 PENDING으로 보정한다. 기존 데이터는 삭제하지 않는다.
- [x] 기존 중복 신고를 점검하는 절차를 제공한다. 중복 발견 시 자동 삭제하지 않고 제약 적용 전에 사용자에게 확인할 수 있도록 식별한다.
- [x] 신고자·대상 종류·대상 ID의 DB 유니크 제약으로 중복을 막는다. 처리 완료 후에도 재신고를 허용하지 않는다.
- [x] 해당 중복 제약 위반만 409로 변환한다. 다른 무결성 오류를 중복 신고로 처리하지 않는다.
- [x] 신고 스냅샷 보존, 서로 다른 사용자의 신고 허용, 동시 신고 시 1건 생성 및 나머지 409를 검증하고 Swagger를 갱신한다.

## Answer

게시글 신고, 스냅샷 보존, 중복 유니크 제약과 기존 H2 상태 보정·중복 점검을 구현했다. 동시 신고와 기존 데이터 보정·중복 보존 테스트를 통과했다.

전체 테스트: 78개, 실패·오류·건너뜀 0개. Standards 및 Spec 리뷰의 확정 발견 사항은 각각 0개다.
