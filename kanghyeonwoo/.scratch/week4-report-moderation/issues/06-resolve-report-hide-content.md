# 06: 신고 처리와 콘텐츠 숨김을 기존 조회에 연결

**What to build:** 사용자가 신고를 HIDE 또는 KEEP으로 종결하고 그 결과를 공개 조회에서 확인할 수 있다. 중복 처리와 부분 성공 없이 최초 결과와 처리 이력을 보존한다.

**Blocked by:** 04: 중복 방지를 포함한 댓글 신고 접수. 01·02·03은 간접 의존성이다. 05는 필수 선행 조건이 아니다.

**Status:** resolved

- [x] PATCH /reports/{reportId}/resolve에서 processorId, action, resolutionReason을 받는다. 존재하는 사용자면 누구나 처리할 수 있고 ADMIN 역할이나 로그인을 추가하지 않는다.
- [x] 처리 사유는 공백 불가·최대 255자다. 잘못된 action·ID·입력은 400, 없는 사용자·신고는 404다.
- [x] HIDE와 KEEP는 상태가 아닌 처리 행동이다. 둘 다 신고를 PENDING에서 RESOLVED로 변경하고 행동·사유·처리자·처리 시각을 기록한다.
- [x] HIDE는 신고 대상만 ACTIVE에서 HIDDEN으로 바꾼다. 댓글 신고로 부모 게시글을 숨기지 않는다. KEEP는 현재 공개 상태를 유지하고 숨김을 복원하지 않는다.
- [x] 같은 대상의 다른 신고를 자동 종결하지 않는다. 이미 숨겨진 대상의 다른 PENDING 신고는 HIDE·KEEP 모두 처리 가능하다.
- [x] 신고 당시 스냅샷을 검토 근거로 보존하며 원문이 수정되었어도 HIDE는 현재 대상을 숨긴다.
- [x] 물리 삭제 대상 또는 논리 삭제 댓글은 KEEP으로 종결할 수 있고 HIDE는 409다. 신고와 스냅샷을 보존한다.
- [x] 이미 RESOLVED인 신고는 재처리 시 409이며 최초 결과·이력을 변경하지 않는다.
- [x] 신고 행 잠금과 하나의 트랜잭션으로 신고 처리 및 대상 숨김을 원자적으로 반영한다. 기존 수정·삭제와 경합해도 결과를 덮어쓰거나 부분 성공하지 않는다.
- [x] 성공은 HTTP 200 및 S200이다. 신고 ID·상태·행동·처리자·처리 시각과 대상 존재·숨김 여부를 반환한다. 삭제 대상은 존재 여부 false, 숨김 여부 null이다.
- [x] 숨김 게시글을 목록·제목 검색에서 DB 페이징 전에 제외하고 상세 조회는 404로 처리한다. 숨김 후 수정해도 HIDDEN을 유지하고 작성자의 기존 삭제 권한은 유지한다.
- [x] 댓글 목록에서는 숨김 안내 문구를 반환하고 검색에서는 제외한다. 삭제 표시를 우선하고 대댓글 관계를 유지한다.
- [x] 과거 검색 이력·검색어 사전·집계 검색량을 유지한다. 신규 검색 결과 유무는 ACTIVE 게시글만 기준으로 판정한다.
- [x] 동시 처리 시 최초 결과 보존, 실패 시 전체 롤백, 여러 신고, 수정·삭제된 대상, 실제 공개 조회 차단 및 기존 CRUD·검색·신고 보존 회귀를 검증한다.
- [x] 관리자가 아닌 사용자 fixture로 API 5개를 시연할 수 있게 하고 Swagger·시연 문서를 갱신한다. 전체 테스트를 통과한다.

## Answer

존재하는 일반 사용자의 HIDE/KEEP 처리, 이력, 잠금·원자적 상태 전이, 기존 조회의 숨김 반영을 구현했다. 동시 처리·수정·삭제 경합, 롤백, 삭제 대상 처리 및 대댓글 삭제 후 신고 보존을 검증했다. moderation-demo와 Swagger 시연 문서를 제공한다.
