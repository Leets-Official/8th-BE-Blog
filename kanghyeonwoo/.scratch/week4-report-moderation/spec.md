# 4주차: 신고 접수 및 검토·처리 구현 계획

상태: 기존 신고 기능과 후속 `DELETED` 게시글 soft-delete 정책을 구현했다. 전체 clean test를 통과했다.

## 목표와 범위

게시글·댓글·신고 도메인을 활용한 API 5개를 추가한다. 신고 중복 방지, 신고 상태 전이, 검토 결과에 따른 콘텐츠 숨김을 하나의 흐름으로 제공한다.
기존 게시글 CRUD, 검색 기능과 신고 스냅샷 보존 정책을 유지하면서 숨김 콘텐츠의 공개 노출을 차단한다.

## 공통 응답

- 컨트롤러 및 예외 처리기는 `ResponseEntity<ApiResponse<T>>`를 반환한다.
- HTTP 상태는 ResponseEntity가 담당하고, JSON 본문은 `success`, `code`, `message`, `data`로 통일한다.
- `code`는 String: 조회·처리 성공 `S200`, 생성 성공 `S201`, 실패는 ErrorCode의 도메인 코드.
- 실패 응답의 data는 null. 기존 기본 과제 API의 숫자 200은 문자열 S200으로 변경한다.
- Swagger 및 테스트는 실제 응답 규격에 맞춘다. CONTEXT.md의 과거 숫자 code 설명도 문자열 비즈니스 코드로 갱신했다.

## API 명세

기존 PostController의 `/posts` 규칙에 맞춘다.

| 기능 | 요청 | 성공 |
| --- | --- | --- |
| 게시글 신고 | POST /posts/{postId}/reports | HTTP 201 / S201 |
| 댓글 신고 | POST /comments/{commentId}/reports | HTTP 201 / S201 |
| 신고 처리 | PATCH /reports/{reportId}/resolve | HTTP 200 / S200 |
| 댓글 목록·본문 검색 | GET /posts/{postId}/comments | HTTP 200 / S200 |
| 신고 목록·스냅샷 검색 | GET /reports | HTTP 200 / S200 |

신고 요청: `{"reporterId": 2, "reason": "욕설이 포함되어 있습니다."}`

신고 응답 data: `reportId`, `targetType`, `targetId`, `status`.

처리 요청: `{"processorId": 1, "action": "HIDE", "resolutionReason": "인신공격 확인"}`

처리 응답 data: `reportId`, `status`, `action`, `processorId`, `resolvedAt`, `targetAvailable`, `targetHidden`.
대상이 삭제되었으면 targetAvailable=false, targetHidden=null로 반환한다.

## 사용자와 권한

- 로그인 및 ADMIN 역할은 이번 범위에 추가하지 않는다.
- 기존 authorId 방식에 맞춰 reporterId·processorId로 DB 사용자를 조회한다. 존재하는 사용자라면 누구나 신고를 처리할 수 있다.
- processorId는 처리 이력에 기록한다. 요청 ID는 인증 수단이 아니며 신고 기능 테스트를 위한 사용자 식별 방식이다.

## 상태와 정책

- ReportStatus: PENDING → RESOLVED. 생성 시 PENDING이며 역전이·재처리는 허용하지 않는다.
- ReportResolutionAction: HIDE / KEEP는 상태가 아닌 처리 행동이다. 처리 결과와 사유, 처리자, 처리 시각을 보존한다.
- PostStatus: ACTIVE → HIDDEN, ACTIVE/HIDDEN → DELETED. DELETED는 소프트 삭제 상태이며 terminal이다. 복원 API는 포함하지 않는다.
- CommentStatus: ACTIVE → HIDDEN. 기존 isDeleted는 삭제 여부로 유지한다. 삭제된 댓글은 공개 상태와 무관하게 삭제 표시를 우선한다.
- HIDE는 대상만 숨긴다. 댓글 신고로 부모 게시글을 숨기지 않는다.
- KEEP는 현재 공개 상태를 유지한다. 다른 신고로 숨겨진 대상을 복원하지 않는다.
- 본인 콘텐츠, 숨김 콘텐츠, 삭제된 댓글은 신규 신고할 수 없다. 숨김 게시글의 댓글도 신규 신고를 제한한다.
- 동일 신고자·대상은 처리 완료 후에도 재신고할 수 없다.
- 같은 대상에 여러 신고가 있으면 선택한 신고만 처리한다. 대상이 이미 숨겨졌어도 다른 PENDING 신고는 처리할 수 있다.
- 신고 접수 후 게시글이 DELETED 상태가 되거나 댓글이 논리 삭제되어도 신고와 스냅샷을 보존한다. 삭제 대상은 targetAvailable=false, targetHidden=null로 반환한다. KEEP로 신고를 종결할 수 있고 HIDE 요청은 409로 거절한다.

## 중복 요청과 동시성

- 신고 접수: 서비스 사전 확인 + DB `(reporter_id, target_type, target_id)` 유니크 제약. 동시 요청에서도 1건만 생성한다.
- 신고 중복 제약 위반만 409 도메인 오류로 변환한다. 다른 무결성 오류를 중복 신고로 오인하지 않는다.
- 신고 처리: 트랜잭션 내 신고 행을 비관적 잠금으로 조회하고 PENDING인지 검사한다. 처리와 대상 숨김은 원자적으로 커밋한다.
- 콘텐츠의 숨김·수정·삭제 경합을 고려해 대상 변경을 잠금 또는 조건부 갱신으로 보호한다. 구현 시 기존 수정·삭제 경로와 잠금 순서를 함께 확인한다.
- 이미 처리한 신고를 재요청하면 409를 반환하고 최초 결과를 덮어쓰지 않는다.
- 기존 DB의 중복 신고를 점검한 뒤 유니크 제약을 적용한다. 기존 상태 필드는 기본값 보정 후 NOT NULL을 적용한다. 영구 H2의 ddl-auto=update에만 데이터 보정을 맡기지 않는다.

## 기존 조회와 연동

- 게시글 목록 및 제목 검색: DB 조회 조건에서 ACTIVE만 선택한 뒤 페이징한다. HIDDEN과 DELETED는 결과에서 제외한다.
- 게시글 상세 및 해당 게시글의 댓글 조회: HIDDEN 또는 DELETED이면 404로 응답한다. 게시글을 DELETED로 바꿔도 게시글과 댓글 행은 보존하며, 부모 게시글이 DELETED인 동안 댓글은 조회·검색·신고할 수 없다.
- 게시글 수정은 숨김 상태를 ACTIVE로 되돌리지 않는다. DELETED 게시글의 수정·재삭제 요청은 404로 처리한다. 작성자는 ACTIVE 또는 HIDDEN 게시글을 기존 권한에 따라 DELETED로 전환할 수 있다.
- 게시글이 DELETED이면 해당 게시글과 그 댓글을 대상으로 접수된 기존 신고는 KEEP로 종결할 수 있지만 HIDE는 409다. 신고 스냅샷은 보존한다.
- 게시글이 DELETED로 전환되면 검색 프로젝션에서 제거한다. 게시글 행과 댓글 행은 보존한다.
- 댓글 목록은 숨김·삭제 댓글의 원문 대신 안내 문구와 구분 가능한 상태를 반환한다. 검색에서는 숨김·삭제 댓글을 제외한다. 삭제 표시가 우선한다.
- 검색 자동완성·통계·데모 시더에서 posts를 직접 읽는 경로가 있는지 점검한다. 숨김 게시글의 본문·제목을 직접 반환하는 경로는 차단한다.
- 과거 검색어 통계는 유지한다. 숨김 후 검색 결과 유무 판정은 ACTIVE 게시글만 기준으로 한다.

## 오류 규칙

| 조건 | HTTP 상태 |
| --- | --- |
| reason/resolutionReason 공백 또는 255자 초과, 잘못된 action·ID 형식 | 400 |
| 본인 콘텐츠 신고 | 403 |
| 사용자·신고·대상 없음, 숨김 콘텐츠 신규 신고 | 404 |
| 중복 신고, 이미 처리됨, 삭제 대상 HIDE, 삭제 댓글 신고 | 409 |

## 목록·검색과 페이징

- 게시글·댓글·신고 목록 모두 data에 items, page, size, totalElements, totalPages를 반환한다. 기존 게시글 목록의 배열 응답도 변경한다.
- page는 1부터, size는 기본 10·최대 100이다. 잘못된 값은 400이다.
- 생성 시각 내림차순, ID 내림차순으로 정렬한다. 검색·상태 필터는 DB 페이징 전에 적용하며 전체 건수도 같은 조건으로 계산한다.
- 댓글 목록은 특정 게시글에 속한 댓글·대댓글을 parentId가 있는 평평한 목록으로 반환한다. 부모가 다른 페이지에 있어도 parentId를 유지한다.
- 댓글의 keyword는 해당 게시글의 댓글 본문을 검색한다. 없으면 목록을 반환한다.
- 신고 목록의 status·targetType·targetId는 선택 조건이며 지정된 조건을 AND로 적용한다.
- 신고의 keyword는 사유·제목 스냅샷·본문 스냅샷 중 하나라도 포함하면 일치한다. 현재 원문을 검색하지 않는다.
- 신고 목록에는 신고 ID·신고자·대상·상태·사유·스냅샷·생성 시각을 제공한다. 대상이 수정·삭제되어도 스냅샷을 보존하고 조회한다.

## 승인된 구현 티켓

| 번호 | 기능 | 직접 선행 티켓 |
| --- | --- | --- |
| 01 | 게시글 목록의 공통 페이징 응답 적용 | 없음 |
| 02 | 중복 방지를 포함한 게시글 신고 접수 | 없음 |
| 03 | 댓글 목록·본문 검색 및 페이징 | 01 |
| 04 | 중복 방지를 포함한 댓글 신고 접수 | 02, 03 |
| 05 | 신고 목록·스냅샷 검색 및 필터 | 01, 02 |
| 06 | 신고 처리와 콘텐츠 숨김을 기존 조회에 연결 | 04 |

각 티켓에 필요한 데이터 보정·API·테스트·Swagger 변경을 포함한다. 공통 응답 통일은 완료했으므로 중복 구현하지 않는다.
05는 06의 필수 선행 조건이 아니다. 신고 생성 응답의 ID로 처리를 검증할 수 있다.

## 완료 기준

- 게시글·댓글 신고 성공 및 신고 당시 스냅샷 보존.
- 같은 신고자 중복 차단, 다른 사용자 신고 허용, 동시 신고 시 DB 1건 및 나머지 409.
- 본인 신고·삭제 댓글 신고·잘못된 입력을 거절하고, 존재하는 일반 사용자의 신고 처리는 허용.
- HIDE/KEEP 처리 결과, 재처리 차단, 두 처리자의 동시 요청 시 최초 결과 보존.
- 숨김 도중 오류 발생 시 신고 상태와 콘텐츠 상태 모두 롤백.
- 다른 신고로 이미 숨겨진 대상, 접수 후 수정·삭제된 대상의 처리 정책 검증.
- 숨김 게시글을 목록·검색·상세에서 차단하고, 숨김 댓글의 안내 문구 및 검색 제외 검증.
- 댓글·대댓글의 평평한 관계와 신고 복합 검색, 모든 목록의 페이징·전체 건수 검증.
- 기존 CRUD, 신고 이력 보존, 검색 이력·검색어 사전·집계 검색량의 회귀 검증.
- 기존 영구 DB의 데이터 보정과 중복 점검을 검증하며 기존 중복 신고를 자동 삭제하지 않음.

완료 시 전체 테스트를 실행하고, API 5개 및 중복·상태 전이·목록 검색을 관리자 역할 없이 Swagger에서 시연할 수 있어야 한다.
