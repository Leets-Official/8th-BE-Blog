# 7주차 과제 - 김현보

AWS EC2 인스턴스를 만들고, Docker로 nginx 컨테이너를 실행해 브라우저에서 접속했다.

## 실습

### 1. AWS 계정 생성
- 무료 플랜으로 가입했다. 크레딧을 넘는 사용분이 자동으로 결제되지 않는다.
- 루트 계정에 MFA(인증 앱)를 등록했다.
- 제로 지출 예산을 만들어, 과금이 생기면 이메일 알림을 받도록 했다.

### 2. EC2 인스턴스 생성

| 항목 | 설정 |
|---|---|
| AMI | Ubuntu Server 24.04 LTS (x86) |
| 인스턴스 유형 | t3.micro |
| 리전 | 아시아 태평양(시드니) ap-southeast-2 |
| 키 페어 | RSA, `.pem` |
| 보안 그룹 | SSH(22): 내 IP만 허용 / HTTP(80): 전체 허용 |

- 무료 플랜 계정은 시드니 리전만 쓸 수 있어서 서울 대신 시드니에 만들었다.
- SSH는 내 IP에서만 접속할 수 있게 열고, nginx 화면을 보기 위해 HTTP(80)는 전체에 열었다.

### 3. SSH 접속 후 Docker 설치
Windows에서는 `.pem` 파일 권한이 넓으면 SSH가 키를 거부한다. 그래서 먼저 본인만 읽을 수 있게 권한을 바꿨다.

```powershell
icacls "leets-week7.pem" /inheritance:r /grant:r "${env:USERNAME}:R"
ssh -i "leets-week7.pem" ubuntu@<퍼블릭IP>
```

```bash
sudo apt update
sudo apt install -y docker.io
sudo systemctl enable --now docker
sudo docker --version
```

### 4. nginx 컨테이너 실행
```bash
sudo docker run -d -p 80:80 nginx
sudo docker ps
```

### 5. 브라우저 접속
`http://<퍼블릭IP>`로 접속해 "Welcome to nginx!" 화면을 확인했다. 스크린샷은 PR에 첨부했다.

실습이 끝난 뒤에는 비용이 나가지 않도록 인스턴스를 중지했다.

## 개념 정리

### EC2, RDS, S3의 역할
- **EC2**: 클라우드에서 빌려 쓰는 서버 컴퓨터다. 스프링 서버나 Docker 컨테이너를 실행하는 곳이다.
- **RDS**: 설치, 백업, 패치를 AWS가 대신 관리해 주는 데이터베이스(MySQL 등)다.
- **S3**: 이미지나 파일 같은 데이터를 저장하고, URL로 꺼내 쓸 수 있는 파일 저장소다.

### Docker Image와 Container의 차이
- **Image**는 앱을 실행하는 데 필요한 코드, 라이브러리, 설정을 묶어 둔 읽기 전용 설계도다. 자바로 치면 클래스에 가깝다.
- **Container**는 그 이미지를 실제로 실행한 프로세스다. 자바로 치면 클래스로 만든 객체에 가깝다.
- 이미지 하나로 컨테이너를 여러 개 띄울 수 있고, 컨테이너를 지워도 이미지는 남는다.

### 8080:8080 포트 매핑의 의미
- `-p 호스트포트:컨테이너포트` 형식이다. `8080:8080`은 서버(EC2)의 8080번 포트로 들어온 요청을 컨테이너 안의 8080번 포트로 전달한다는 뜻이다.
- 컨테이너는 격리된 네트워크에서 돌기 때문에, 포트를 매핑하지 않으면 밖에서 접근할 수 없다.
- 이번 실습의 `80:80`은 EC2의 80번 포트를 nginx 컨테이너의 80번 포트에 연결한 것이다.
- 스프링 앱을 `8080:8080`으로 띄운다면, EC2 보안 그룹에서도 8080번 포트를 열어야 외부에서 접속할 수 있다.

### 배포가 실패했을 때 확인할 항목
- [ ] 보안 그룹 인바운드 규칙에 필요한 포트(22, 80, 8080 등)가 열려 있는가
- [ ] 인스턴스가 실행 중이고 상태 검사를 통과했는가
- [ ] 퍼블릭 IP가 맞는가 (인스턴스를 중지했다가 다시 시작하면 IP가 바뀐다)
- [ ] `https`가 아니라 `http`로 접속했는가
- [ ] `docker ps`에 컨테이너가 떠 있는가 (없으면 `docker ps -a`, `docker logs <컨테이너ID>`로 원인 확인)
- [ ] 포트 매핑(`-p`)이 올바른가, 같은 포트를 다른 프로세스가 쓰고 있지 않은가
- [ ] 서버 안에서 `curl localhost`가 되는가 (된다면 보안 그룹이나 네트워크 문제, 안 된다면 컨테이너 문제)
- [ ] 디스크(`df -h`)나 메모리(`free -h`)가 부족하지 않은가 (t3.micro는 메모리가 1GB다)
- [ ] SSH가 안 되면 키 파일 경로와 권한, 사용자 이름(`ubuntu`), SSH 허용 IP를 확인했는가
